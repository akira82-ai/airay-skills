# 输出格式规范

本文档说明 `idea-to-post` 技能的最终输出格式要求。

---

## Markdown 格式规范（必填）

所有文章内容必须以标准 Markdown 格式输出。

### 格式元素说明

| 格式元素 | 用途 | 示例 |
|---------|------|------|
| 标题层级 | 章节标题（仅二级） | `## 01｜引言` `## 02｜核心观点` |
| 列表 | 并列要点、步骤说明 | `1. 项目 1` |
| 表格 | 去 AI 味前后对比 | `原句 / 原段` `去 AI 味后` |
| 代码块 | 展示代码、数据、原始素材 | ` ```markdown ... ``` ` |

### 标题格式规范

统一格式：`## N｜标题`

1. 使用中文竖线 `｜`（不是英文竖线 `|`）
2. N 为数字序号（01/02/03...）
3. 标题简洁明了，能概括该部分内容

示例：

```markdown
## 01｜引言
## 02｜核心观点
## 03｜实践案例
## 04｜深度分析
## 05｜总结与展望
```

### 代码块规范

统一使用 markdown 语言：

````markdown
这里是代码内容
````

### 列表规范

统一使用有序列表：数字加点 `1.`

```markdown
1. 要点1
2. 要点2
3. 要点3
```

### 去 AI 味对比表规范

最终产物后必须追加 `## 去 AI 味前后对比`，使用 Markdown 表格。对比表是强制输出，不是可选附录。如果文章保存为 Markdown 文件，对比表必须写入同一个文件末尾，不能只在聊天回复里展示。

```markdown
| 原句 / 原段 | 去 AI 味后 |
|---|---|
| 原来的 AI 味句子或段落 | 修改后的自然表达 |
```

对比表只保留两列，不展示修改原因。默认展示 5-8 条关键修改；如果修改点不足 5 条，展示实际数量。即使没有明显修改，也必须输出对比表；如确实没有修改点，写 1 行说明原文已通过检查。缺少标题或两列表格时，最终输出不合格。结束前必须检查最终产物或目标文件，确认存在 `## 去 AI 味前后对比` 和 `| 原句 / 原段 | 去 AI 味后 |`。

---

## 输出前检查清单

在最终输出前，必须确认以下事项：

### 格式检查

1. 标题格式统一：`## N｜标题`（使用中文竖线｜）
2. 代码块统一使用 markdown 语言
3. 整体格式遵循标准 Markdown 语法
4. 列表使用正确的符号（仅使用 `1.`）
5. 中英文之间有空格（AI Agent 而非 AIAgent）
6. 中文语境用全角标点（，。！？：；）

### 内容排版检查

1. 层级清楚：标题、正文、素材、备注能一眼区分
2. 段落短：一个段落只讲一个小意思，避免大段堆叠
3. 留白稳定：标题和正文之间留空，段落间距一致
4. 阅读路径自然向下，不让素材打断正文
5. 图片、代码、引用、数据靠近相关解释
6. 素材说明放在下方，文字简短
7. 页面不拥挤，避免密集文本块
8. 标点、编号、英文词、数字写法保持一致

### 内容检查

1. 核心观点明确
2. 有具体案例（时间/地点/人物/数字）
3. 有情绪时刻或转折点
4. 有独特观点（反直觉/未发现技巧/可引用原话）
5. 有原始素材引用（文档/对话/数据）
6. 故事闭环完整
7. 专业概念已经用普通人能懂的话解释

### 去 AI 味检查

1. 像真人表达，不像 AI 总结
2. 句子有长短变化，有自然停顿
3. 没有整齐排比、口号式结尾、过度对称句式
4. 没有"事实上/本质上/某种程度上"等套话
5. 没有"首先/其次/最后/综上所述"等模板结构
6. 没有"随着/近年来/不仅而且"等常见开场和连接句式
7. 没有"不是……而是……/不仅是……更是……/一方面……另一方面……"等模板对称句式
8. 抽象词已经降级成人话或具体动作
9. 句长和段落节奏有变化
10. 口语颗粒使用克制，没有油腻口语化
11. 命中禁用句式的句子已经重写，不是轻微替换
12. 连续 2 句有 AI 味的段落已经重写
13. 对比表能看到清晰改写，不是微调
14. 最终产物后紧跟 `## 去 AI 味前后对比`
15. 对比表只有两列：`原句 / 原段`、`去 AI 味后`
16. 如果保存为文件，文件内已包含对比表
17. 对比表不缺失；缺失则不得结束输出

---

### 章节数量建议

1. 最少：3 个部分
2. 推荐：5 个部分
3. 最多：7 个部分

## 常见格式错误

### 错误示例

````markdown
# 一级标题（不应该使用）

## 1|引言（使用英文竖线）

### 三级标题（不应该使用）

- 要点1
- 要点2

```
代码块语言是 js（应该统一用 markdown）
```
````

### 正确示例

````markdown
## 01｜引言

正文内容...

## 02｜核心观点

1. 要点1

2. 要点2

```markdown
代码内容
```
````

## 语言风格规范

### 格式禁用

1. 严禁使用破折号（——）
2. 严禁使用粗体（**文字**）→ 用普通段落或中文标点「」代替强调
3. 严禁使用引用块（> 文字）→ 改为普通段落
4. 严禁使用无序列表（- 文字）→ 用编号列表或直接叙述

### 词汇禁用

1. 事实上
2. 本质上
3. 某种程度上
4. 值得注意的是
5. 换句话说
6. 众所周知
7. 综上所述
8. 总而言之
9. 由此可见
10. 不难看出
11. 在当今社会
12. 随着、近年来 作为开头
13. 不仅……而且……
14. 不是……而是……
15. 不仅是……更是……
16. 一方面……另一方面……
17. 真正重要的是……
18. 这背后的本质是……
19. 此外、另外、与此同时、不仅如此
20. 深入探讨
21. 旨在
22. 赋予
23. 助力
24. 方法论
25. 范式
26. 生态

### 处理原则

1. 能删除就删除。
2. 能直接说结论，就直接说结论。
3. 需要转折时，用自然说法，不用模板连接词。
4. 需要解释时，用场景、例子、对比，不用抽象套话。

## 快速参考

### 标点符号速查

| 语境 | 标点 | 示例 |
|-----|------|------|
| 中文 | 全角 | ，。！？：； |
| 英文/代码 | 半角 | ,.!?/:; |
| 中英文间 | 空格 | AI Agent |
| 省略号 | 两个字符 | …… |

### 段落规范速查

| 规范 | 要求 |
|-----|------|
| 段落长度 | 不超过 5 行 |
| 句子节奏 | 长短句交替，有自然停顿 |
| 层级 | 标题、正文、素材清楚分开 |
| 留白 | 段落间距稳定，不挤压 |
| 对比表 | 最终产物后追加两列表格；保存为文件时写入同一文件 |
