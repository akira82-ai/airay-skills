# Prompt Engineering

来自 lesson3：高级提示词和提示工程。

## Core Principle

高级提示工程不是加更多强硬语气，而是补足关键上下文，并控制模型的执行过程。

## Context Layers

复杂任务优先补四层上下文：

- 业务目标层：为什么做，服务哪个目标。
- 场景约束层：时间、角色、资源、风险偏好。
- 已知事实层：数据、规则、历史决策、输入材料。
- 验收标准层：什么输出可用，什么输出不可用。

上下文要与决策直接相关，不能把材料无差别塞进提示词。

## Process Control

根据任务复杂度选择控制方式：

- 先规划再执行：先让模型列步骤、检查点、风险，再写正文。
- 先发散再收敛：先给多个方案，再按标准筛选。
- 大任务分步推进：拆成理解、提纲、正文、审校、交付。
- 少样本示范：给 1-3 个高质量样例，覆盖主流场景和边界情况。
- 元提示词：先定义好提示词标准，再让模型生成具体提示词模板。

不要给太多相似样例。样例应突出结构与判定标准。

## Quality Governance

高质量提示词要让输出可检查、可追溯、可复盘：

- 反驳自己：要求模型给出反例、风险和不成立条件。
- 前后一致：检查术语、数字、结论、限制是否矛盾。
- 因果闭环：每个建议都说明原因、影响和动作。
- 结论可验证：关键结论附证据类型和验证方式。
- 信息落盘：连续迭代时要求保留版本、修改点和未决问题。
- 多语检索单语输出：检索可多语，最终输出锁定单一语言。

## Repair Prompts

当优化版跑出来仍不理想，给用户一条可复制的修复提示词：

```text
请基于上一次输出做二次修订。
重点修复：
1. 【具体偏差】
2. 【缺失模块】
3. 【格式问题】

保持原任务目标不变，不新增未经提供的事实。
请输出修改后版本，并列出 3 条关键修改点。
```

## When To Use Advanced Patterns

- 输出总是空泛：补上下文四层和验收标准。
- 输出方向跑偏：先规划再执行。
- 方案质量不稳：先发散再收敛。
- 任务太大：分步推进。
- 团队要复用：用元提示词生成模板和变量。
- 决策风险高：加入反例、证据和验证动作。
