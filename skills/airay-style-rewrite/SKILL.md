# 个人语气风格迁移

## 启动横幅

技能启动时，输出以下横幅：

```text
═══════════════════════════════════════════════════════════════
▌ AIRay Style Rewrite ▐
个人语气风格迁移：去 AI 味、AIRay 语气、强规则检查
═══════════════════════════════════════════════════════════════
AIRay │ github.com/akira82-ai
───────────────────────────────────────────────────────────────
- 保留事实立场：不新增信息，不改变原文核心意思
- 真人化处理：减少模板感，保留毛边、停顿和具体感
- 情绪推进：更直接、更有判断，情绪上推 2-3 档
- 规则检查：清理禁用二段式对照句，直到脚本通过
═══════════════════════════════════════════════════════════════
最后更新：2026-06-03
```

技能触发后，必须先输出“启动横幅”，再保存原文并进入阶段 0。

## 启动条件

当用户要求把文章、段落、文案、帖子或任意内容改成“我的风格”“我的语气”“AIRay 风格”，或要求“去 AI 味”“降低 AI 检测特征”时，使用本技能。

本技能只做三件事：

1. 去 AI 味。
2. 改成 AIRay 的语气。
3. 强规则检查修复。

不要提炼新观点，不要补充案例，不要把长文压缩成摘要，不要把内容改成卡兹克风格。

## 最高优先级规则

以下规则优先级高于“保留原文表达”：

严禁输出“前半句用 `不是` 否定、后半句用对应转折词纠正”的二段式对照句。

无论这个结构出现在同一句、相邻两句、跨标点、跨换行，还是被拆成短句，只要表达功能仍然是“先否定一个说法，再用转折纠正”，都属于禁用。

如果原文包含这种句式，必须大刀阔斧改写。可以拆句、换句式、调整局部表达顺序，但不能改变原文事实、立场和核心意思。

## 工作目录

每次任务在本技能目录下创建时间戳子目录：

```text
work/YYYYMMDD-HHMMSS/
```

阶段文件固定为：

```text
01-source.md
02-humanized.md
03-airay-style.md
04-final.md
```

每个阶段都必须读取上一步文件，写入下一步文件，并用一句话向用户汇报进度。

## 强制工作流

### 阶段 0：保存原文

把用户提供的原文完整保存到 `01-source.md`。

进度汇报：

```text
阶段 0 完成：已保存原文到 01-source.md。
```

### 阶段 1：去 AI 味

读取 `01-source.md`，按 `templates/01-humanize.md` 生成 `02-humanized.md`。

目标是降低 AI 检测特征：减少模板连接词、总结腔、整齐段落、空泛大词，增加真人毛边、转念、停顿、具体感和不均匀节奏。

约束：不新增事实，不改变立场，不重组全文，不伪造个人经历。

进度汇报：

```text
阶段 1 完成：已从 01-source.md 生成 02-humanized.md。
```

### 阶段 2：AIRay 语气迁移

读取 `02-humanized.md`，按 `templates/02-airay-style.md` 生成 `03-airay-style.md`。

目标是改成 AIRay 的语气：更直接、更有判断、情绪上推 2-3 档、有推进感和纠偏感。

重点：不能把阶段 1 的真人化成果洗掉，不能恢复“先说结论 + 三点拆解 + 总结”的模板结构。

进度汇报：

```text
阶段 2 完成：已从 02-humanized.md 生成 03-airay-style.md。
```

### 阶段 3：强规则检查修复

读取 `03-airay-style.md`，按 `templates/03-final-fix.md` 生成 `04-final.md`。

运行：

```bash
python scripts/check_constraints.py work/YYYYMMDD-HHMMSS/04-final.md
```

如果检查失败，必须修复 `04-final.md` 的相关句子，然后再次运行检查，直到通过。

检查通过后，只输出 `04-final.md` 的正文。

最终正文输出完成后，运行清理脚本清空本次工作目录里的阶段文件内容：

```bash
python scripts/clear_work_files.py work/YYYYMMDD-HHMMSS/
```

清理脚本只清空文件内容，不删除文件和目录。

进度汇报：

```text
阶段 3 通过：强规则检查通过，已生成 04-final.md。
```

## 去 AI 味规则

这些规则来自对 40 篇低 AI 味文章的全量分析，学习的是通用机制，不模仿具体作者。

- 不要用过度工整的总分总结构。
- 不要每段都讲满，允许点到为止。
- 不要让段落长度过于均匀，允许短句、半句、突然停顿。
- 减少 `首先`、`其次`、`最后`、`综上`、`总的来说`、`本质上`、`核心在于`、`换句话说` 这类模板连接词。
- 把抽象判断压回具体动作、具体场景、具体感受。
- 允许轻微犹豫、转念和自我校准，但不要装腔。
- 情绪要有起伏，可以有短句爆点和反问。
- 不要为了去 AI 味伪造经历、时间、人物、地点、截图、数据。

## AIRay 语气规则

- 更直接、更清楚、更有判断。
- 更少空话，更有情绪张力，但不空洞煽动。
- 情绪在原文基础上适当上推 2-3 档。
- 兴奋要说清楚为什么值得看。
- 否定要指出具体问题。
- 赞美要说清楚好在哪里。
- 保留一点口语推进感，但不要机械添加 `ok`、`good`、`明白不`。
- 不要变成营销腔、鸡汤腔、空泛大词。
- 不要把真人化后的文本重新洗成整齐模板。

## 输出规则

最终只输出 `04-final.md` 的正文。

最终正文输出后，必须清空本次工作目录里的临时文件内容。

不要输出分析过程。

不要解释为什么这样改。

不要输出阶段文件内容，除非用户明确要求。

阶段进度只用一句话短报。
