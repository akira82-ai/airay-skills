# 个人语气风格迁移

## 启动横幅

技能启动时，输出以下横幅：

```text
═══════════════════════════════════════════════════════════════
▌ AIRay Style Rewrite ▐
个人语气风格迁移：五步文档链路、AIRay/IP 语气、强规则修正
═══════════════════════════════════════════════════════════════
AIRay │ github.com/akira82-ai
───────────────────────────────────────────────────────────────
- 原文锁定：保留核心意思，标记硬事实和可补边界
- IP 语气：更直接、更有判断、更有纠偏感
- 真人化处理：主体感、口语颗粒、情绪毛边、节奏变化
- 强规则修正：清理禁用句式、模板词、抽象大词和报告腔
═══════════════════════════════════════════════════════════════
最后更新：2026-06-03
```

技能触发后，必须先输出“启动横幅”，再保存原文并进入阶段 0。

## 启动条件

当用户要求把文章、段落、文案、帖子或任意内容改成“我的风格”“我的语气”“AIRay 风格”，或要求“去 AI 味”“降低 AI 检测特征”时，使用本技能。

本技能只做五件事：

1. 原文锁定。
2. AIRay/IP 语气初改。
3. 真人化去 AI。
4. 自我校准与结构收口。
5. 强规则修正。

不要把长文压缩成摘要，不要把内容改成卡兹克风格。

## 最高优先级规则

以下规则优先级高于“保留原文表达”：

- 每一步必须读取上一步阶段文件。
- 每一步必须先读取对应 `references/` 文件，再执行本阶段。
- 如果对应 reference 无法读取，必须停止并告知用户，不得凭记忆继续。
- 每一步必须写入下一步阶段文件。
- 第 1 步不判断原文类型，不判断改写强度。
- 第 1 步允许合理补表达性经历、场景和案例，但不能编造硬事实。
- 第 3 步不清理模板连接词，模板连接词统一留到第 5 步强规则修正。
- 第 4 步不削弱强判断，自我校准只用于增强可信度。
- 第 5 步是强规则修正，不是事实审查。

严禁输出“前半句用 `不是` 否定、后半句用对应转折词纠正”的二段式对照句。

无论这个结构出现在同一句、相邻两句、跨标点、跨换行，还是被拆成短句，只要表达功能仍然是“先否定一个说法，再用转折纠正”，都属于禁用。

## 工作目录

每次任务在本技能目录下创建时间戳子目录：

```text
work/YYYYMMDD-HHMMSS/
```

阶段文件固定为：

```text
01-source.md
02-source-lock.md
03-ip-voice.md
04-humanized.md
05-calibrated.md
06-final.md
```

每个阶段都必须读取上一步文件，写入下一步文件，并用一句话向用户汇报进度。

除 `01-source.md` 和 `06-final.md` 外，阶段文件底部必须写入内部检查区：

```text
<!-- INTERNAL CHECKLIST
- 已读取上一步阶段文件
- 已读取对应 reference
- 已完成本阶段核心规则
-->
```

内部检查区只用于阶段传递，最终输出时不得展示。

## 强制工作流

### 阶段 0：保存原文

把用户提供的原文完整保存到 `01-source.md`。

进度汇报：

```text
阶段 0 完成：已保存原文到 01-source.md。
```

### 第 1 步：原文锁定

读取：

```text
01-source.md
references/01-source-lock.md
```

写入：

```text
02-source-lock.md
```

`02-source-lock.md` 必须包含原文全文、核心意思、硬事实、必须保留信息、可补表达性细节边界和 `INTERNAL CHECKLIST`。

进度汇报：

```text
第 1 步完成：已从 01-source.md 生成 02-source-lock.md。
```

### 第 2 步：IP 语气初改

读取：

```text
02-source-lock.md
references/02-ip-voice.md
```

写入：

```text
03-ip-voice.md
```

目标是先解决“是谁在说话”：更直接、更有偏好、更敢下判断、更少中立说明、更有纠偏感。

进度汇报：

```text
第 2 步完成：已从 02-source-lock.md 生成 03-ip-voice.md。
```

### 第 3 步：真人化去 AI

读取：

```text
03-ip-voice.md
references/03-humanize.md
```

写入：

```text
04-humanized.md
```

目标是保留 AIRay/IP 语气，并加入主体感、口语颗粒、情绪毛边、不工整节奏、反抛光粗糙感、具体动作词和混杂语域。

不要在本阶段清理 `首先`、`其次`、`综上`、`本质上`、`核心在于` 等模板连接词。

进度汇报：

```text
第 3 步完成：已从 03-ip-voice.md 生成 04-humanized.md。
```

### 第 4 步：自我校准与结构收口

读取：

```text
04-humanized.md
references/04-calibrate-close.md
```

写入：

```text
05-calibrated.md
```

目标是让文本像“一个人刚想明白一件事”：保留强判断，只在必要处补边界、思考过程和自然收口，不得把真人毛边全部磨平。

进度汇报：

```text
第 4 步完成：已从 04-humanized.md 生成 05-calibrated.md。
```

### 第 5 步：强规则修正

读取：

```text
05-calibrated.md
references/05-hard-rule-fix.md
```

写入：

```text
06-final.md
```

目标是用硬规则清掉 AI 味词汇、句式和报告腔。写入 `06-final.md` 后必须运行：

```bash
python scripts/check_constraints.py work/YYYYMMDD-HHMMSS/06-final.md
```

如果检查失败，必须修复 `06-final.md` 的相关句子，然后再次运行检查，直到通过。

进度汇报：

```text
第 5 步通过：强规则检查通过，已生成 06-final.md。
```

## 输出规则

检查通过后，只输出 `06-final.md` 的正文。

最终正文输出后，运行清理脚本清空本次工作目录里的阶段文件内容：

```bash
python scripts/clear_work_files.py work/YYYYMMDD-HHMMSS/
```

清理脚本只清空文件内容，不删除文件和目录。

不要输出分析过程。

不要解释为什么这样改。

不要输出阶段文件内容，除非用户明确要求。

不要输出 `INTERNAL CHECKLIST`。
