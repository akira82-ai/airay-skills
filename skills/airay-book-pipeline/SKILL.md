# airay-book-pipeline

## 启动横幅

每次启动、以及每次阶段切换时输出：

```text

阶段门禁：出口条件自检 → 验收单 → 你说通过，才走下一步
═══════════════════════════════════════════════════════════════
磊叔 │ 微信：AIRay1015 │ github.com/akira82-ai
当前书：《{书名}》│ 当前阶段：{N} {阶段名}（{状态}）│ 打回：{次数}
═══════════════════════════════════════════════════════════════

```

## 最高铁律：阶段门禁状态机

1. **四态状态机**：每个阶段只有四个状态——`未开始 → 进行中 → 待验收 → 已通过`。
2. **"已通过"只有一个来源：用户明确批准**（"通过""可以""进下一步"）。自检全绿只算"待验收"，本技能永不自批。
3. **打回循环**：用户说不行 = 打回意见**原话记入进度文件** → 留在本阶段修改 → 重新自检 → 重新出验收单。打回次数不设上限，改到通过为止。
4. **禁止跳步**：阶段 N 未标"已通过"，不得开始阶段 N+1 的任何实质动作。唯一例外：用户显式说"跳过"，必须在进度文件记录"用户授权跳过 + 原话"。
5. **批量通过可以，合并验收不行**：用户可以一次说"1–4 都通过"，照办并记录；但每阶段仍须各自出过验收单，不允许"这几个阶段一起算过了"。
6. **断点续传**：跨 session 只认 `0-进度.md`。新 session 第一件事读它、横幅报状态、从"下一步"继续；进度文件不在，视为新书或询问，不凭记忆推进。
7. **单阶段单焦点**：进行中的阶段不做后续阶段的活（资料阶段不写题、写作阶段不改总纲方向）。发现后续阶段的线索，记入进度文件待办。

## 文档与技能分工（本技能是调度器，不复制内容）

| 对象 | 角色 |
|---|---|
| `zh/sop/100问系列书-成书SOP-v1.0.md` | 阶段 1–9 的动作清单 / 产物 / 出口条件（执行到哪阶段读哪节，不整篇读）；阶段 10 英文版以本技能"各阶段作业规则"为准 |
| `airay-100-questions` 技能 | 阶段 1–5 "问"的方法论（画像卡、搜索框架、题干铁律、质检清单） |
| `/dbs` 等调研技能 | 阶段 1 的全网搜集与深度分析 |
| `airay-md2book` 技能 | 阶段 8 封装成书 |

仓库锚点：书的工作目录为 `zh/100-questions-of-{slug}/`（仓库根 `100-questions-of-ai-agent`）。SOP 升级版本号后，本技能只改引用路径中的版本号。

## 答案体成文规则（所有书默认，用户裁定，优先于 SOP 阶段 6 指引）

分工总则：AI 只负责"挑出该题要填入的原文 → 仅做语序和逻辑上的优化 → 直接填入"；语气与文字的润色由用户手工完成，AI 不得代劳——AI 直接成文 AI 味过重。

1. **原文直取**：答案内容直接取资料原文，不做"基于资料改写"式的再创作。
2. **AI 允许的动作（仅此三项）**：挑选该题要填入的原文段落；调整语序、理顺逻辑；删除无意义的文字。英文等外文资料忠实全量翻译成中文。
3. **AI 禁止的动作**：调整语气、润色措辞、统一行文风格、添加过渡语或过渡词、提炼、总结、摘要、压缩信息、添加自己的观点或概括句。语气和文字一律留给用户手工改。
4. **多引用合并**：一题引用多处（如 5 处）→ 揉成一个整体，约 3~4 段，逻辑串通即可。
5. **不标出处**：成文不保留出处标注；题→资料的对应关系在生成过程中内部维护（阶段 5 登记表照旧）。
6. **目标文风**：平实自然的中文书面语，出版级别——AI 填充阶段刻意贴近原文、宁保留原貌不为流畅加笔，最终质感由用户手工润色达成。写作风格基线已废弃。
7. **红线**：改后每段的信息量必须与原文一一对应——没有多出原文没有的结论，也没有丢原文的信息。阶段 7 按此抽检，发现提炼/摘要即打回。

## 各阶段作业规则（#15/#16 实战沉淀，所有书默认）

**阶段 4 · 创作规则**
- 答案说明格式定版：每题「钩子 → 判断 → 能抄的动作」三件套。
- 溯源方式定版：出处由 `2.2-资源登记表` 承接，正文不写资源信息。

**阶段 5 · 问题生成**
- 验收单默认附 3 道抽样题，用户不翻文件即可判。

**阶段 6 · 内容生成**
- 生成禁则：① 正文不带「资源：…」围栏代码块（溯源统一走资源登记表）；② 章首不写版本行；③ 图注只用图片 alt 自带斜体，不另起图注行；④ 案例一律「例如，」直接带出——禁"一个 X 案例"框架、禁量词/形容词包装、禁"谁举的例"中介层。
- 打回反哺：每次打回，除意见原话入档外，当堂判断能否前置为生成禁则；能则写入本节或 `4-答案说明`，下一题立即生效，不许同类问题重复出现。

**阶段 7 · 内容审查**
- 并行对源审查：只读子代理分章审查（每路两章），五项核对写死——信息保真 / 翻译忠实 / 数字核对 / 口径标注 / 禁词引用体。
- 主 agent 必须复核子代理裁决，误判驳回后才进修复清单；子代理裁决不是终判。
- 标准产物：《7-审查修复记录》《7-数字复核清单》。
- 补丁纪律：修复方案先 grep 验证原文（对齐空格与措辞）再入清单；机器终检脚本先自跑通过，再当验收证据。
- 断点续传：每章审完即落盘进度；限额中断或新 session 从断点续跑，不重扫已审章节。
- 不阻塞问题挂账：发现不阻塞发布的问题，记入 `0-进度.md` 待办并标复核时点（默认"阶段 8 封装前"），阶段 8 出口自检核销。

**阶段 8 · 封装成书**
- 封面流程：先问用户"自备还是出三问"，自备为默认；三问仅在用户要方案时启用。
- 每轮打回后用 python-docx 机器验证残留清零，再交下一轮验收。
- 出口自检含"遗留项已复核或用户豁免"。

**阶段 9 · 发布**
- 出口条件：营销文案发布 + 正式链接回填两份主帖（中文主链接必填；英文版次链接未发布前留占位，阶段 10 落地后回填）。
- 发布节奏表归用户，本技能交付到链接回填为止。

**阶段 10 · 英文版**
- 地址定案（开工即定，禁止临场起名）：仓库内路径 = 仓库根 `100-questions-of-{slug}/`（与 `zh/` 平级，slug 与中文版一致）；对外 URL = `https://github.com/akira82-ai/100-questions-of-ai-agent/tree/main/100-questions-of-{slug}`。定案即写入 `0-进度.md`，中途不改名。
- 全书英文化：每章一个英文 md，英文标题 slug 命名、序号与中文章号严格对齐；翻译沿用"答案体成文规则"的忠实全量口径，不提炼、不摘要、不压缩；书名英文定案与中文同源。
- 题号互通校验：题号与中文版完全一致；断号是有意设计（中英双版题号互通依赖），机检按断档白名单放行，不判错。
- 图片同步：中文版引用图片同步到英文目录 `images/`，图注 alt 英文化。
- GitHub 发布：commit + push 后验证 URL 可访问，未 push 不算发布。
- 收官验收：出口四项全过——① URL 可访问；② 题号互通校验过；③ 双链接回填完成；④ 地址已入进度文件。验收单附 1 章英文样章。

## 工作流

### 每次启动：定位（必做，不可跳）

1. 用户说**开新书** → 主题不明确就追问，不建目录；明确后建 `zh/100-questions-of-{slug}/` + `0-进度.md`（模板见下）→ 进阶段 1。
2. 用户说**继续某本书** → 读该书 `0-进度.md` → 横幅报状态 → 执行"下一步"。
3. 没指明哪本 → 列出所有含进度文件的在写书及各自阶段，让用户选。

### 阶段执行循环

1. 读 SOP 对应阶段的**动作清单**与本技能「各阶段作业规则」，逐项执行；该调技能调技能（阶段 1 调研、阶段 5 出问、阶段 8 封装分别按分工表委托）。
2. **自检**：对照该阶段出口条件逐项核验；能用命令验证的跑命令，输出贴进验收单当证据。
3. 出**验收单**（格式见下），进度置"待验收"，结束回合等用户。
4. 用户**通过** → 更新 `0-进度.md`（状态行 + 阶段日志 + 下一步）→ 横幅切下一阶段。
5. 用户**打回** → 意见原话入进度文件 → 回到第 1 步修改 → 重新自检出单。

### 验收单格式

```text
═════════ 阶段 {N} 验收单 · 《{书名}》 ═════════
产物：
  ✓ {文件名}（已落盘，{一句话说明}）
抽样：
  ✓ {3 道题 / 3 段答案}（阶段 5、6 必附，其余阶段可省）
出口条件核对：
  ✓ {条件}（证据：{命令输出 / 核对结果}）
  ✗ {未达项}（正在补：{动作}）
──────────────────────────────────────────
⏳ 待你验收：回复「通过」进阶段 {N+1}；
   说哪里不行，我改完重新交这单。
```

## 失败条件

出现以下情况不要硬闯：

- 书目录或进度文件缺失/损坏 → 先和用户确认后重建状态，再干活。
- 出口条件依赖用户提供的东西（X/YouTube 手工搜索结果、画像确认、封面三问）没到位 → 进度挂起并明确列"等你提供"，不代答不硬凑。
- 同一阶段被打回 **3 次** → 停止闷头改，先把分歧点摆出来和用户对齐方向。
- 用户要求"一口气写完不用确认" → 拒绝跳过门禁；可以连续干活提速，但每阶段验收单照出，用户口头快速通过即可。
